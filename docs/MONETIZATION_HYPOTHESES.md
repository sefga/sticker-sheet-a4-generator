# 💡 Бэклог гипотез монетизации StickerFit (Monetization Hypotheses)

> **Статус документа**: Исследовательский бэклог (Research Backlog).  
> **Критическое правило**: В кодовую базу StickerFit **НЕ ВНЕДРЯЕТСЯ НИКАКОГО ПЛАТНОГО КОДА, ПЕЙВОЛОВ ИЛИ ПОДПИСОК** до тех пор, пока базовый продукт не наберет первые 100–1000 активных независимых пользователей и не будет доказан явный спрос на расширенные возможности.  
> **Базовый продукт**: Навсегда остается 100% бесплатным, без регистрации, client-side first и открытым под лицензией MIT.

---

## 🧭 Принцип валидации спроса

Вместо преждевременного написания платежного шлюза (Stripe, CloudPayments) мы применяем принцип доказательной валидации:
1. Фиксация потребности через опрос обратной связи и GitHub Issues.
2. Ненавязчивые маркеры интереса (кнопка «Хочу эту функцию в будущем» $\to$ подсчет кликов).
3. Интервью с 5–10 реальными владельцами малого бизнеса / типографий.
4. Только при устойчивом интересе $\to$ проектирование надстройки или Pro-модуля.

## 🎯 План действий на текущем этапе

1. **Сейчас (Фаза 1 — Baseline & Trust)**:
   - 0 платных функций.
   - Развивать доверие, удобство, 100% точность печати и виральность.
2. **При достижении 100 активных пользователей (Фаза 2 — Signal Gathering)**:
   - Проанализировать результаты Feedback Loop («Подошел ли макет для печати?»).
   - Выявить наиболее часто запрашиваемые улучшения (H1 vs H2).
3. **При достижении 1000 активных пользователей (Фаза 3 — Pilot Experiments)**:
   - Рассмотреть реализацию наиболее востребованной гипотезы (вероятнее всего, H2: Сборный лист нескольких наклеек).
